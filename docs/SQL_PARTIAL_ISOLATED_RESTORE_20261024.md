# SQL 部分隔离恢复演练（2026-10-24）

## 结论：五表结构、四表数据恢复通过，不是完整 SQL 回滚

从本次当前冷备份的真实 SQL 归档，在全新、无网络的 MySQL 8.0.46 实例中恢复了网关五张表的结构和其中四张表的数据。四表行数与归档提取时在 SQL VALUES 元组边界上计算的期望完全一致。目录快照表仅恢复结构，**有意不导入其大体量数据**。

因此本演练证明这些表的归档可解析、DDL 和四表数据可被同版本 MySQL 实际加载，不能证明全五表数据恢复、应用语义、目录快照重建、生产回滚或完整播放。

## 为什么不直接恢复全量

初始预算核对：根盘可用约 2.95 GB，媒体盘约 13.73 GB。真实归档解压为 5,042,631,699 字节；网关五表在原库分配约 4.69 GB，另需 MySQL 初始化、日志及临时空间。完整恢复会违反媒体保留线 10,241,399,522 字节，根盘也无法容纳。可用内存约 10.10 GB，但已有约 3.65 GB swap 使用，未采用大 tmpfs 或内存过量承诺来绕过磁盘预算。

## 真实权限发现与认证读取

只读核对发现媒体盘为 `fuseblk ... allow_other`，即使创建时请求 0600，归档及父目录的实际模式仍为 0777。不能再把媒体归档称为“文件系统实际 0600”。父代理随后完成归档的 AES-256-CBC + PBKDF2 加密及独立随机密钥 HMAC-SHA256 认证封装，完整解密比对成功后移除明文；密钥与可信 seal 保留在根盘私有目录，实际 0600。

本演练先独立按**根盘可信 seal**核对整个密文 HMAC、密文 SHA256 和长度，再允许解密。不能信任媒体盘旁可被更改的 manifest 自己声明的 MAC。密文 SHA256：

`438a88eb1c8dfb29b91ffc49648e2225ab7ffa62af4b9bf641b52ab29364c8c5`

通过 OpenSSL 解密流及 gzip 流读取，不在媒体盘重新落明文。解压到 EOF 时 gzip CRC 验证通过。根盘临时 pass 文件实际 0600，结束后删除；没有输出密钥、签名 URL、nonce 或任何 SQL 值。

## 有界提取

先进行内存合成测试：保留五个精确网关表结构，只保留四表 INSERT，拒绝未知表、未闭合字符串、真实多行 INSERT 和未知命令。实际归档为当前服务器生成的 mysqldump；这不是可安全执行任意外来 SQL 的通用解析器。

实际读取边界：单行 16 MiB、总输入 6 GiB、筛选输出 32 MiB、独占创建 0600，精确允许五张网关表，保留必要 mysqldump SET / 锁 / DDL 封套。归档实际最大行 1,044,179 字节，共 7,856 行。

| 表 | CREATE 次数 | INSERT 行数 | 原始 INSERT SQL 字节 | 提取期望数据行数 |
| --- | ---: | ---: | ---: | ---: |
| alist_encrypt_strategy | 1 | 1 | 151209 | 724 |
| alist_encrypt_file_meta | 1 | 21 | 21858796 | 49560 |
| alist_encrypt_range_compat | 1 | 1 | 7013 | 39 |
| alist_encrypt_dir_sync_status | 1 | 1 | 277 | 1 |
| alist_encrypt_dir_snapshot | 1 | 7606 | 5020605850 | 未计数，数据全部排除 |

这里 INSERT “行数”是 SQL 语句物理行数，不等于记录数。四表记录数按引号、反斜杠转义和 VALUES 元组深度计算，不从 INSERT 语句条数猜测。

筛选结果 **22,025,849 字节**，SHA256：

`085f6165238903cbc44838c84636cbe0e8090890deab7f49cc3b7a47f5f43a1c`

首次提取误对被排除的约 5 GB 快照字符串逐字节计数，达到 240 秒期限后失败关闭，半成品删除、临时 pass 删除；修正为跳过快照 INSERT，仅对四表统计元组后，重新认证和完整提取成功。没有将超时产物作为有效输入。

## 独立 MySQL 资源与恢复结果

- 固定镜像 ID：`sha256:6cd09145362dfe6831b14545de3d5fd6cc75c37cfd6ef8561429c1fc73518b39`，MySQL 8.0.46。
- 全新私有根盘数据目录；不挂载生产目录、冷备份原件或云配置，不传生产 DSN。
- `network=none`、无端口、`skip-networking`，仅在容器内经 Unix socket 访问。
- 内存上限 512 MiB、CPU 1，buffer pool 64 MiB、redo 8 MiB，关闭 binlog 和 performance_schema。
- 开始根盘可用量至少 2,650,000,000 字节；新数据目录分配上限 320,000,000 字节，根盘硬保留 2,147,483,648 字节；总期限 120 秒。
- 原先更高的开始预算曾阻止启动，没有绕过后冒称执行。父代理审阅小表实测体积后明确批准上述有限预算。

第一次实际启动时，mysqladmin ping 误将初始化阶段的临时服务器当作最终就绪；目标 schema 尚未创建，导入失败。未保存当次 stderr，不能伪称已证实某个具体 MySQL 错误码。该实例停止后仅移除本次新建的失败目录，保留筛选 SQL、归档和冷备份。修正为同时等待最终 entrypoint 初始化完成标记和目标 schema 实际存在，再允许导入。

唯一一次修正重试完成，耗时 **54.13 秒**：

| --- | ---: | --- |
| alist_encrypt_strategy | 724 | 一致 |
| alist_encrypt_file_meta | 49560 | 一致 |
| alist_encrypt_range_compat | 39 | 一致 |
| alist_encrypt_dir_sync_status | 1 | 一致 |

五表 SHOW CREATE TABLE 摘要私有保存；没有将原始结构或数据输出到公开文档。实例最终正常停止，**exited / ExitCode 0**，没有遗留运行实例。最终根盘可用约 **2,520,264,704 字节**，未违反硬保留线。原网关、MySQL、上传器和下载器没有被本演练停止或改写。
