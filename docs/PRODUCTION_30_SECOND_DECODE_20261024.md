# 生产 30 秒实际解码验收（2026-10-24）

## 范围与结论

**通过：生产已完整交付对象的前 30 秒音视频真实解码。** 这不是媒体字节复制测试，也不代表 60 分钟连续播放、手机首帧或全文件解码通过。

对象匹配当前唯一 `full_plaintext_sha256` 持久化收据，明文总量 **1,602,702,460 字节**，来源摘要前缀 `7783`。使用当前已暖生产 v521；没有强制冷态、重启服务或修改配置。没有输出媒体路径、文件名、账号、密码、令牌或签名 URL。

## 凭据隔离与严格网络预算

FFmpeg 5.1 不支持 `-/headers` 文件加载；未把 Authorization 放进子进程 argv、URL 或环境。使用本次独占的临时 HTTP 转发器，绑定 `127.0.0.1` 随机端口，仅支持固定 `/media` 的 GET / HEAD，只能访问在内存绑定的这一个生产对象。

- 上游 Basic 凭据只在 Python 内存中；FFmpeg argv 仅含不带凭据或文件名的 loopback `/media`。
- 禁止代理与重定向；只接受正确 206、精确 Content-Range 及长度，HEAD 如出现则要求 200 和精确长度。
- Range 语法严格匹配，不能转发任意路径、URL、方法或请求头。仅传回必要的 Content-Length / Range / Type / Accept-Ranges。
- 请求上限 **16**，累计读取上限 **128 MiB**，每次 I/O 至多 **5 秒**，整轮总期限 **90 秒**。
- 实际 **15 个 GET，全部 206**；上游读取 **94,306,456 字节**，转发 **93,454,488 字节**；没有触及字节或请求上限，拒绝计数 0、上游错误 0。
- 此数是转发器实际消费的明文量，不是 CDN 线路总流量；服务器可能已经预读 / 发送额外数据。FFmpeg 的尾部 moov 探测和分段回读导致多次 Range 与读前量，不能把 30 秒等同于只传输了精确编码包字节。
