# P1 root MySQL metadata backup component (format v1)

## API / ownership boundary

`mysqlstore.BackupMySQL(ctx, dsn, BackupOptions)` is a standalone synchronous component, **not wired into runtime owners, scheduling, retention or shutdown**. `ValidateMySQLBackup(ctx, path, maxBytes)` is basic envelope/hash validation, not restore. Mandatory positive `MaxBytes` includes the final manifest; mandatory positive `Timeout` bounds the entire DB session and cooperative local work. Caller controls a private existing directory and a single filename. No shell, generic mysqldump, CLI credentials, service objects/config/schema mutation, or local MySQL startup is involved.

This exports **all actual tables in the explicitly selected dedicated metadata database**, using authoritative `information_schema.TABLES`, real engine values, `SHOW CREATE TABLE`, and `SELECT *`. No hardcoded table whitelist or active-row filter: current strategy, file_meta, range_compat, dir_snapshot, dir_sync_status, future tables, inactive rows and all columns are included. Database must contain only this intended metadata component; do not point this API at a shared users/config database. Root Bolt users, original-name audit/occupancy/reverse indexes, external OpenList/config, and mobile SQLite are **not** included. No cross-store atomic snapshot is claimed.

## Transaction / DDL limits

A dedicated connector uses one connection, `sql.BeginTx` with `LevelRepeatableRead` and `ReadOnly: true`. Fixed go-sql-driver/mysql v1.7.1 supports these options, but does **not** expose an option emitting `WITH CONSISTENT SNAPSHOT`. A first real consistent InnoDB `SELECT ... LIMIT 1` pins the read view **before table export**. This is equivalent to a consistent snapshot established at that first read (including an empty InnoDB table). Never issue a second `START TRANSACTION WITH CONSISTENT SNAPSHOT` inside `sql.Tx`: that would implicitly commit and break the guarantee. The snapshot includes only committed DB transactions at pin time. Store pending buffers are neither drained nor claimed included; this is not an application flush barrier.

All base tables must report InnoDB, otherwise `ErrBackupUnsupported` refuses publication. Views/non-InnoDB/empty DB are also refused. A single transaction streams every table; concurrent committed updates cannot create old/new mixed associations, and uncommitted rows are excluded.

MySQL transaction snapshots **do not snapshot schema**. Fingerprints before/after export cover actual names, engines and SHOW CREATE (columns/defaults/types/indexes/constraints/partition definitions); any observed difference returns `ErrBackupSchemaChanged` and does not publish. Only the volatile table `AUTO_INCREMENT` counter is normalized because ordinary inserts can change it. Metadata locks held by reads can delay DDL until transaction completion; the backup's metadata lock acquisition has `lock_wait_timeout=1`, all SQL calls have context, and driver dial/read/write timeouts are bounded by the total timeout.

**Caller must exclude migration/concurrent DDL for the whole operation.** Fingerprints detect observed drift, not transient/reverted DDL or changes after the last check. This is not an unconditional schema-snapshot guarantee. Existing table DDL may block behind acquired locks; newly created tables are tested as observable drift. A DDL lock-bound stress fixture has not yet been cloud-verified.

## Typed NDJSON format and sensitive payload

Each table record contains name, engine, normalized full DDL, ordered column names, database type names, nullability. Row records contain ordered typed values. The last line is the manifest (version/component/consistency/sensitivity/times/source commit/Go and driver/server provenance/schema SHA-256/payload SHA-256/payload bytes/rows/tables). Digest covers all preceding **exact bytes including newlines**. Caller-supplied SourceCommit must be a non-secret actual build commit; uncommitted implementations need honest provenance. No DSN, password, signed URL or row values enter manifest automatically.

Kinds: `null`, `bytes` (canonical standard base64), `string`, `bool` (true/false text), `int64`, `uint64`, `float64` (round-trip Go text), `time` (UTC RFC3339Nano). Unknown driver values and non-finite floats refuse export. SQL NULL/nil byte slice and empty non-nil bytes stay distinct. Integer values beyond JavaScript's 53-bit range are never JSON numbers. DECIMAL remains exact driver bytes, not float conversion. Binary/nonce/payload bytes stay byte-exact. Database type + full DDL retain unsigned widths, DECIMAL scale, time precision, generated/invisible columns and constraints for a future typed importer. SELECT * does not include MySQL invisible columns: **invisible columns are explicitly unsupported and rejected**, not silently omitted.

The backup connector forces `parseTime=false`, `loc=UTC`, session `time_zone='+00:00'`: DATE/DATETIME/TIMESTAMP/TIME preserve raw driver text, fractional precision and zero dates. DATETIME is a wall-clock value, not an inferred absolute UTC instant; TIMESTAMP retrieval is normalized to UTC. This dedicated connector does not alter Store's historical local-time DSN behavior. Unsupported specialized values fail rather than coerce. MySQL GEOMETRY is exported as raw native driver bytes (SRID prefix + geometry binary representation), **not WKT/GeoJSON and not an import-ready ST_GeomFromWKB argument**. Future restore must interpret server-specific spatial representation/DDL and validate types; this format does not promise portable geometry conversion.

Actual file_meta fields include complete V3 geometry (`size`, `ciphertext_size`, `content_version`, `header_len`, `nonce_field`, `chunk_size`, `kdf_iterations`), raw URL/auth scope/sign and original/encrypted paths; all other store/cache/checkpoint/stat fields also remain. Full database backup deliberately includes persisted transfer secrets for completeness, unlike default sanitized sync exports. Treat artifact as highly sensitive; 0600 is not encryption. An independent encryption/authorization/expiry-invalidation design remains required before exposing this as a runtime feature.

## Stage / publication / resources

Private 0700 same-directory stage, exclusive 0600 artifact, checked context and actual output byte budget per record, streaming DB cursor (not paginated cursors), payload hash + envelope validation, file fsync, same-filesystem hardlink no-replace publication and directory fsync. Existing target never overwritten, failed stage cleaned, prior good artifacts untouched, no rotation. Manifest is in the single atomically published artifact, avoiding a two-file publication gap. Directory/ancestors must remain caller-controlled; private-directory checks do not defend hostile owner/ancestor rename races. Cooperative file I/O cannot interrupt a stuck kernel fsync/write; budget is output bytes, not a strict heap/packet cap (one large DB value/row or schema may allocate before rejection). Directory fsync failure after link reports “published but directory durability unconfirmed”, not a false unpublished success; caller should not blindly retry/rotate. No generalized rollback is claimed.
