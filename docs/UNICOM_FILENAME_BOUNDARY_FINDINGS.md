# 联通云盘文件名边界实测

## 范围与日期

2026-10-14，针对实际 Docker 部署的 OpenList `/156联通云盘/encrypt` 挂载进行受控测试。通过上游 `/api/fs/put` 上传非敏感小文件，不经过加密代理命名转换。两个随机独立测试目录均通过 `/api/fs/remove` 清理并返回 code 200。没有重命名、删除或覆盖用户已有文件。

## 确认结果

| 上传名称长度（ASCII，包含 `.bin`） | 返回 code | 上游保存长度 | 完全一致 |
|---:|---:|---:|:---:|
| 97 | 200 | 97 | 是 |
| 99 | 200 | 99 | 是 |
| 100 | 200 | 100 | 是 |
| 101 | 200 | 100 | 否 |
| 120 | 200 | 100 | 否 |
| 200 | 200 | 100 | 否 |
| 255 | 200 | 100 | 否 |
| 256 | 200 | 100 | 否 |

上传含中文的名称：110 字符/290 UTF-8 字节保存为100字符/260字节；122字符/324字节保存为100字符/258字节。该观察支持本挂载上传链路的限制是字符数量，不是UTF-8字节数。尚未独立定位到网盘服务还是OpenList驱动中的具体实施点。

## 数据覆盖风险

两个不同105字符名称，其前100字符相同，上传不同内容：A、B均返回200，但最终目录只有一个对应文件，读取所得内容是B。证实该链路静默截断后的同名写入会覆盖此前内容。

这意味着：不得截断密文名称；不得只加短摘要便声称绝无碰撞；对新写入应协调完整原名称的持久化映射、目标占位及冲突拒绝。不得用“先查404再上传”声称实现跨进程原子无覆盖。

## 重命名不是同一限制

101、120字符的重命名在测试中返回200且列表原样保存。100字符重命名成功后的立即列表未观察到目标；之后另一次重命名可找到该源，可能涉及可见性时序。200字符重命名返回上游登录失败。不能从这次结果确定重命名最大长度，也不能把上传100字符上限等同所有操作上限。

## 与现有异常的对应

上游原始WebDAV目录包含1675个`.bin`文件，其中19个违反完整编码名长度规则；这19个全部100 ASCII字符。指定异常文件去掉`.bin`后为96字符，完整编码名需正文4的倍数+1校验字符；96字符不符合。现象与实测上传截断规律吻合，构成明确根因链路证据；历史具体上传工具和时点无法从保留日志恢复。

该文件内容头为AES-CTR V2（AECTR2）。上游密文2505875436字节；解密代理Range读取返回2505875404字节总长及合法MP4 `ftypisom` 文件头。文件名恢复失败不等于内容解密失败。

## 安全编码预算

ASCII加密名、`.bin`外部后缀、完整CRC：

`4 * ceil(plaintext_utf8_bytes / 3) + 1 + 4 <= 100`

对应明文最多69 UTF-8字节、最终密文名称最多97 ASCII字符。原始完整名称必须另外保留，而非丢弃长标题。此预算仅用于已确认的本联通上传链路；不推广到其他存储和旧文件源路径解析。

### 候选写入策略

显式配置 `alistServer.filenameWriteLimits`，只为本次授权的 `/156联通云盘/encrypt` 设置 100，不改变其他挂载或旧文件源路径的编码规则。完整原名称及原始显示路径先存入本地 Bolt 持久化审计；超长名称使用 UTF-8 安全前缀、完整原名 SHA-256 的 16 个十六进制字符及原扩展名，然后完整编码及生成 CRC。摘要不能恢复原名，备份记录不可删除。

受保护的同步整文件 API PUT／WebDAV PUT 使用同一物理目标占位、目标不存在验证、有界结果响应验证、实际保存名称及密文大小验证，并在持久化完成后才发布成功。已占用、失败或已完成目标均拒绝重复写入；断点续传不支持此策略，不能通过异步任务绕过。失败占位不自动释放，因为上游可能已经保存部分对象。`v2026.10.14.414` 的 API rename 与 DAV MOVE/COPY 只有部分目标长度检查，API move/copy 没有同等保护，且各入口没有完整原名审计迁移，不能称为安全mutation支持。P0补齐版在源或目标子树与配置保护范围相交时对rename/move/copy统一返回501 `protected_operation_unsupported`，不向上游发送请求；畸形/无法确定路径400。未配置或明确不相交操作维持既有行为。此能力拒绝不是实测rename长度极限，未来按独立安全迁移阶段启用。

**占位限于同一个本地 Bolt 数据库，不是 MySQL 分布式锁。外部写入者及其他实例仍可能在检查后写入目标；上游未提供已验证的原子不覆盖接口，不能保证此类竞争绝不覆盖。** 部署必须保留挂载的 data 目录和审计数据库，不可多实例分别持有独立数据库却宣称同等保护。

### 候选旧异常显示恢复

只在明确配置的挂载中识别完整文件名解码失败的 `.bin` 对象。独立读取有限的解密前缀，严格验证实际响应范围、加密几何及 V2 nonce，确认视频容器签名后持久化具有凭据、规则、来源、大小及有效期约束的别名。名称使用可反向映射的 `orig_…` 加正确视频扩展名；不凭空恢复已丢失的完整历史标题，也不修改网盘实际名称或内容。

V1／V2 有限前缀识别受支持；V3 暂不支持此自动恢复，未知格式仍保留原显示，不能猜测后缀。识别不是全文件完整性校验。每次目录最多等待四个冷候选、总等待预算八秒；后台探测限流且有限超时，失败五分钟冷却。冷目录可能需要多次访问逐步完成，确认结果持久化后不在每次热列表重新探测。别名记录有效期为24小时，授权或规则变更不能复用旧确认。
