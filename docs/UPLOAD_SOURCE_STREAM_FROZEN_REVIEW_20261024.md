## 新增保证与代价

- 使用 O_NOFOLLOW / O_NONBLOCK 打开非空普通文件，绑定设备号、inode、大小及纳秒 mtime / ctime；单个上传生命周期持有 FD，不将 FD 留在长期验收缓存。
- 解码前生成完整 SHA256 和 1 MiB 分块清单；所有 ffprobe / ffmpeg 子进程通过 `pass_fds` 读取 `/proc/self/fd/N`；解码后再次核对完整清单与路径 / FD 身份，不退回路径解码。
- 每一完整分块先读取到私有不可变缓冲并校验，再向 Requests 返回该块的任何字节。已缓冲的正确字节不因源之后变动而变成坏字节；后续改变的分块不会被释放。
- PUT 完成前要求声明长度全部消费、流哈希和再次完整源复核；禁止重定向与流重放。源变更或不确定传输结果返回 `stop_round`，不自动重试或切换目标。
- 每客户端非阻塞锁覆盖解码和上传；`finally` 关闭 FD、清除当前绑定并释放锁。审查曾撞到锁改动的中间版本，最终冻结版已核实释放逻辑，并新增连续成功 / 失败恢复 / 并发拒绝回归。

代价是额外完整扫描及一次固定 FD 的整片解码，**不是性能优化**。1 MiB 分块及有界清单避免制作完整源快照；本版本不保证对抗能篡改内核、进程或文件系统身份的特权攻击者。

## 不保证原子云对象，不能自动释放声明

晚变源可能已有正确前缀到达真实上游，留下部分物理对象和失败、独占的声明。修复保证的是**损坏分块不发送**，不是“上游没有任何残留”，更不自动删除对象、释放声明或绕过完整远端明文读回 / 收据 / 删源门槛。

安装前仍需现有收据、删源、容量及 review 流程针对协调集的离线回归；安装只能在持续暂停下备份、精确匹配摘要并一次协调替换三个源文件。是否恢复服务须独立判断，不能凭这份冻结报告、CI 或假媒体测试解除门禁。Torrent piece 真实性和目标媒体身份仍是另一层准入问题，不能只靠“能完整解码”代替。
