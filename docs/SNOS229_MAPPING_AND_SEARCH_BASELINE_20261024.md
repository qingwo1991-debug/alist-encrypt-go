# 当前规则映射与旧镜像搜索基线（2026-10-24）

## SNOS-229 当前映射核对

本轮仍是 parentproof 现网，不是新发行镜像部署后的验收。

- 当前规则来自配置 JSON 的 `alistServer.passwdList`；规则读取实现直接使用配置快照，无需打开生产 Bolt。
- 配置有两条启用规则，目标展示路径只匹配一条 `aesctr`、加密文件名、`.bin` 规则。
- 在内存中按当前 Go 文件名算法（完整文件名含扩展名、MixBase64、PBKDF2 与 CRC6）计算，结果与历史物理文件名完全一致。本轮没有发现规则或密码映射漂移。
- 上游同一父目录、不强制刷新的一次完整页响应 HTTP 200 / 业务码 200；内容 1821 条，总数 1821，响应 514,574 字节，在 1 MiB 上限内，没有该历史物理文件名。
- 这比“首 100 条未找到”更明确，但仅证明目标不在当前 **API 可见完整列表**。缓存、隐藏规则、ACL 和虚拟回退仍使它不成为权威物理缺失证明。不能据此解除预留、覆盖旧对象或宣称文件已经删除。
- 本轮有界诊断共四次网络调用，没有打开生产数据库、强制刷新、恢复、释放、PUT / DELETE、下载正文或重启。

结合之前代理固定 503 错误，目前仍是受管播放内容几何 / 元数据确认失败；没有新增证据证明早期 filename claim 拒绝是当前 503 的直接原因。

### 进一步绕过 OpenList 缓存的提供商只读核对

实际 OpenList 4.2.7 WoPan 驱动没有 `Getter`；已有父目录缓存不含目标时，`internal/op/fs.go` 可以不重新请求提供商，直接使精确对象查询失败。因此此前精确 `fs/get` 500 / DAV 404 不构成另一份新鲜物理证据。

核实 [SDK v0.1.5 的 QueryAllFiles 参数](https://github.com/OpenListTeam/wopan-sdk-go/blob/v0.1.5/api-fs.go) 后，使用临时诊断夹具直接访问固定官方源，保持数字分页参数、个人空间、默认根 0、当前存储 5 的内存令牌；仅请求 `QueryAllFiles`，没有下载链接、回收站或写操作。先验证精确唯一的目标目录及提供商 ID，再遍历其子项；每页 100，禁止重定向、每页 256 KiB / 10 秒、全程 90 秒上限，重复 ID 拒绝。临时夹具先通过协议与边界模拟，现场结束后已删除，没有新增生产管理接口。

现场 2.79 秒完成：根目录 1 页，目标目录 19 页，子项 **1821**，精确物理文件名命中 **0**。这与 OpenList 当前可见列表一致，排除了“只有 OpenList 旧目录缓存漏掉、提供商当前 live 目录实际仍含该名字”的简单解释。

但提供商分页没有已验证原子快照保证，此次只读范围也不含其他目录、重命名和回收站。结果只能称当前个人 live 目录 API 没有命中该精确名称，**仍不能宣称物理数据彻底删除，更不授权解除 claim、覆盖或删除**。后续需要历史对象 ID、移动 / 改名记录或其他可靠来源继续定位；不能靠无限重试补成功。

## Ctrl+K 搜索旧镜像基线

只读探针使用当前配置扫描身份，通过宿主回环上游登录取得真实会话，再将该上游原始 Authorization 发送给旧代理 `/api/fs/search`。没有借用本地管理 JWT；输出仅保留状态、业务码和响应长度。

| 请求 | HTTP | 业务码 | 有界响应字节 |
| --- | --- | --- | --- |
| 上游登录 | 200 | 200 | 243 |
| 同一会话直接上游搜索 | 200 | 200 | 64 |
| 同一会话旧镜像代理搜索 | 200 | 401 | 73 |

这再次复现旧版代理未保留搜索调用者会话的问题；不能当作新镜像修复失败。PR104 已包含对应修复，但现网仍未切换，必须在升级后用同一凭据语义对照验证。

## 切换约束

现场上传仍有真实进度：观察到同一上传连接 TCP 已确认字节由 926,201,247 增至 959,678,807，不能因长时间无完成日志就判断挂死。现有上传器和调度器没有已验证的“仅暂停新接单、完成在途交付”接口；`quiet` 或 SIGTERM 可能打断当前交付。

等待自然完成、校验完成与真实空闲后，才阻止自动调度重新启动，并在服务确实退出后成套备份和受控切换。当前未改配置、未停上传器、未重启网关，未发送回收站 prepare / clear。秘密及原始诊断仅留私有目录，不附公开报告。
