# Torrent 来源真实性与持久绑定：后续修复边界（2026-10-24）

**状态：只读设计，不是已实现或通过验收。上传器持续暂停。** 固定 FD、全解码和分块 SHA 解决的是验收字节与发送字节一致性；不能单独证明它们符合原 torrent，或证明影片标题 / 发布者真实性。

## 已确认缺口

`downloader_backend.py` 的 `_validated_piece_completion` 明确只验证传输位图；mover 的选中完成计数、终态和普通文件长度也没有重新验证 piece SHA1。即使计数全满、媒体能解码、随后远端 SHA 与源一致，也可能只证明一致上传了错误来源。

现有后端会对原始 info 字节切片计算 infohash，torrent 原始元数据及 btih 在部分已知添加路径持久记录；这可作为来源锚点，不能根据文件名、扩展名、找不到 RPC 任务或落盘目录反向猜测来源。Magnet 尚缺可信完整元数据时必须保留待复核。

## 最小后续设计

1. 新纯离线、有界模块解析 torrent，绑定**原始 info 字节**而非重新编码后的字典。拒绝重复键、尾随 / 截断 / 歧义编码、危险相对路径及符号链接；仅支持明确识别的 v1 协议，v2 / hybrid 未实现时不得套用 SHA1 假设。
2. 在受控添加 / 导入时持久记录任务所有者、下载根、来源种类、原始元数据 SHA256 / infohash、有序全文件清单、选中索引和 piece 参数。显式登记的可信 HTTP / direct 来源另走准入；未知历史来源不能退回“当普通 HTTP”放行。
3. mover 创建发布事务前，对全部选中文件涉及的完整 piece 做 SHA1 校验。字节偏移来自**完整有序清单，包括未选中文件**；分片可能跨多个小文件，不能只读取单个相邻文件。边界邻接缺失、短读、变源、超时或预算不足均保留整个受控选中范围。
4. 去重交叠分片。额外邻接读取最多为每个**连续选中区间**两端各 `piece_length-1`，不是所有离散选择全局只多两片。限制元数据、piece 数、单片内存及总墙钟，超限不能部分通过。
5. 同次读取计算选中文件完整 SHA256，核对选中与邻接 FD 的设备号 / inode / 大小 / mtime / ctime 前后不变。结果绑定元数据摘要、infohash、选中索引 / 分片区间、源 SHA、指纹、所有者及版本。
6. 来源证明必须进入 fsync 的 mover 事务与发布绑定；独立上传器可见目标前先有 pending 证明，最终提交后才能放行。硬链接会改变 ctime，不能把旧五元组盲用到新路径，需区分 pending / committed 并核对 inode 与 SHA。
7. 上传器在 pinned guard 得到完整 SHA 后、远端探测 / PUT / 去重或切片提交前核对来源证明；解码后再次核对。保护不仅新 PUT，也覆盖已有远端对象的提交与删源分支。来源证明进入持久交付记录，但不冒充远端读回证明。
8. 缺少证明、邻接源或原始元数据时保留源、torrent 和任务，不自动释放 failed claim，不用本轮代码修复作为删源依据。
