# WebDAV 原名读取与上传凭据解耦

## 现场证据

本机 Docker `alist-encrypt` 的镜像修订为 `2753284de85bb666b093ebf3a46de8d477f01873`。
目标文件在目录 `/156联通云盘/encrypt`，名称含 `WA-596.part003.mp4`。
2026-10-17 07:08–07:10（+08:00）多次 PROPFIND 在约 0.09–0.22ms 返回 404。
只读请求核实正文为 `Protected filename unavailable for this scope`。
用户反馈同手机、网络与源，安卓端 WebDAV 可立即打开。

## 根因与修复原则

旧实现把上传凭据的原始 Authorization/Cookie/Proxy-Authorization 摘要与 WebDAV 读取凭据摘要直接比较。不同 token 或认证形式不等于不同资源读取权限，不能把上传时的凭据快照当永久读 ACL。

修复必须满足：

- 完整原名审计、占位、写入 scope、规则指纹和状态不重写，不删除历史；
- 仅 complete 且当前规则匹配的记录可作为私有路径候选；
- 使用当前请求身份向配置上游精确 raw DAV 路径执行 Depth:0 授权验证，不使用服务账号或上传旧 token；
- 不能仅凭任意 207 判定授权成功，需匹配响应资源与成功属性；
- 映射仅绑定当前请求；真正 GET/HEAD/PROPFIND 继续执行当前 caller 的上游请求；
- 模糊映射、权限拒绝、规则/上游切换和验证失败均 fail closed；
- 大库不能因固定 4096 条总数阈值全部失败，无原名存储的普通读取保持兼容。
