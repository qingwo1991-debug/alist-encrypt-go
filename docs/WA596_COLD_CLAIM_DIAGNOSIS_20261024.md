# WA596 历史对象的冷副本预留诊断（2026-10-24）

## 结论

该历史逻辑对象的生产 404 不是本次可证实的“上游物理文件不存在”。当前冷副本显示：**唯一预留为 failed，且没有显式失败对象只读恢复记录**。生产保护路径因此拒绝逻辑名称。随后获得授权的两次有界上游只读请求中，精确物理路径的 PROPFIND 返回 207，密文长度与原预留完全一致；但取 32 字节的 GET 返回 302，按禁止重定向策略停止，**尚无内容头、可解密前缀或完整性证明**。

不能将“物理元数据可见”改写为“文件已恢复”，也不能把逻辑保护 404 当作释放预留、覆盖上传或删除旧对象的理由。

## 冷副本读取范围

只以 bbolt ReadOnly 模式打开当前已停服复制出的可信备份，未打开生产 Bolt，未调用 Store 启动迁移，未复制或修改数据库。精确原始逻辑路径仅在内存筛选，不公开物理名称、源 origin、令牌、密码、scope 摘要或签名 URL。

数据库读取阶段没有网络请求；读取前后文件大小及 mtime 一致。临时诊断程序仅使用标准库与已有 bbolt 缓存，Go 离线运行在 30 秒限额内完成，无仓库源代码修改。

## 为什么生产是 46 字节的 Protected filename 404

代码路径：

1. `internal/handler/webdav.go:142–149` 调用 `hasInvalidProtectedFilenameScope`；invalid 为真时输出 `Protected filename unavailable for this scope`，加换行共 46 字节，HTTP 404。
2. `internal/handler/media_name_recovery.go:108–118` 获取预留。failed 记录先尝试 `bindRecoveredFilename`；没有成功绑定后，`saved.Status != FilenameComplete` 条件直接拒绝。
3. `internal/handler/filename_recovery.go:106–117` 要求 additive recovery 存在且有效。冷副本没有 recovery 桶，因此该条件不成立，无需远端请求就拒绝。
4. trusted_local 只影响正常 complete 分支的远端授权路径，不会把 failed 当 complete，更不会绕过恢复证明。

因此，**当前已证实的阻挡谓词是 failed 审计 + 无显式恢复记录**；证据不支持把原因归于 origin 漂移、规则指纹漂移、读索引未就绪或多个同路径预留。原始 FilenameRecord 没有 `CompleteVerified` 字段，不能补造一个布尔值；其 status 本身明确不是 complete。

## 单独授权的两次物理只读核实

父代理随后明确授权，使用当前配置的扫描 DAV Basic 身份，对冷记录中的精确物理路径执行至多两次读取。同机上游连接、每次 10 秒、响应最多 256 KiB、不走代理、不跟随任何重定向；没有刷新参数、provider 遍历、管理 API、云写入或本地 claim 写入。

| 请求 | 结果 |
| --- | --- |
| 上游原始物理 PROPFIND Depth 0 | **207**，893 字节 XML、1 个 response；成功属性的 getcontentlength=**2036812728**，等于预留密文长度 |
| 上游原始物理 GET bytes=0-31 | **302**，169 字节；未跟随 Location、未输出 URL，无可解析的内容头 |

这将“逻辑保护拒绝”与“物理元数据当前可见”区分开了。但上游元数据可能来自其缓存，302 也不证明最终源站可达；本次没有最终对象字节、明文前缀、全文件哈希、解码或上传完成证明。

## 下一条安全恢复路径（本轮未执行）

- 保留 failed 原审计和独占写预留；不改成 complete，不解除占用，不覆盖云对象。
- 合法生产管理会话取得后，可评估 `POST /enc-api/recoverFilename`；该操作**会增加本地恢复记录，因此不属于本次只读诊断，未调用**。不能伪造 JWT、猜测 / 重置密码绕过管理认证。
- 请求需要合法本地 `Authorizetoken`，并显式提供当前上游读取方 `Authorization`；接口不应用配置服务凭据替代调用者权限。
- 该接口先复核原预留唯一性、当前规则、密文名称绑定、远端精确密文大小，再执行有界解密视频前缀验证，成功才在配置修订栅栏下增加恢复证据。失败审计保持 failed，返回的 recovered 也不是上传完成或全文件恢复。
- 每次 recovered 读取仍重验当前上游访问、几何和有界对象身份，不能用旧管理员证明代替当前读取权限。
- 获得前缀证据后，仍需独立完整明文读回 / 解码与必要的来源 SHA256 比较，才可以宣称完整媒体恢复或考虑后续源删除门槛。

本报告不涉及 SNOS229 的物理遍历结论，不能据此判断 SNOS229 消失或恢复。
