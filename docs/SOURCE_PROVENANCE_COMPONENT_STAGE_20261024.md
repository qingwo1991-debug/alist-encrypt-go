## 私有持久来源账本

冻结模块 SHA256：`b4fcfbbde9f8acbe8e7c35c8f21a25143e702bbcc6148cebce4fc80ff148c3d6`。

- 对原始逐片证明、原始清单、完整选择与所有文件绑定做严格一致性校验；持久 PENDING 后，显式提交 SOURCE_ADMITTED。pending 不能授权上传。
- 私有 owner-only 0700 目录、0600 单链接记录、逐级 nofollow、内容寻址、不可覆盖、文件及目录 fsync；损坏 / 不完整 / 非规范 JSON、错误上下文或根替换失败关闭。
- 原源授权必须同时匹配原始五元组与实际 pinned guard 的完整 SHA256。没有路径重绑、发布指纹转换或删源 API。
- 独立 **38 项原有测试通过，0.164 秒**，另 **5 项对抗检查通过，0.026 秒**；冻结核心及账本摘要前后不变。

## 提交前的来源 registry

冻结模块 SHA256：`4a91203f0ddc21d778b22f9388fab383199b5e3b4996e2515964d503cf242088`。

- 持久记录受控原始 v1 torrent、固定 owner / 预留 GID、host 根目录 inode、完整有序清单和显式选择，返回前 fsync；只支持 torrent_v1，未知 / magnet 缺清单 / direct 不自动回退。
- native 提交确认必须为同一 GID 和非空精确原始 infohash；confirmed 读取进一步逐项核对完整 RPC 文件顺序、路径、偏移、长度、选择与 root。元数据匹配不是完整字节证明。
- 同来源范围和全局 GID 单次保留，不确定提交不得自动新建任务；丢 locator、部分登记或同源重新下载需显式复核，不以方便重试换掉持久 fence。
- 独立 **27 项测试通过，0.161 秒**，另 **8 组对抗检查通过，0.102 秒**。一次对抗夹具恢复成 0644，模块正确拒绝，修正夹具到 0600 后通过，不是放宽生产权限。

## 仍有的边界

私有 UID / root 保管是信任边界，owner 标签及自摘要不是调用方认证、发布者认证或影片语义认证。同 UID / root 被攻破不在这些一致性检查的保证范围。时间预算为协作检查，不能打断内核阻塞读取；stat 不是不可变快照，上传期间仍须原有逐块验证流保护。

实际 backend 的来源登记、mover 的任务 / RPC 快照映射和可恢复发布编排、uploader 的所有早期分支与持久收据绑定仍需完整协调验收。初版不提供切片派生证明或源 / 任务清理；**原源必须保留至完整云端明文读回和持久绑定收据后，再另行审查清理协议**。组件审查、模拟网络和微小真实硬链接不等于生产接入、真实上传 / 云端恢复或可以恢复服务。
